# مشغل موسيقاك — مشغل موسيقى محلي بدون نت (PWA)

مشغل موسيقى شخصي يعمل من **ملفاتك على جهازك فقط**: بدون حساب، بدون شبكة، بدون إعلانات، وبدون أي تبعيات خارجية. ملفات ثابتة (static) بالكامل — لا خطوة بناء ولا كود خادم.

> الأغاني لا تترك هاتفك أبدًا: التشغيل والوسوم والأغلفة كلها تُقرأ وتُخزَّن محليًا في IndexedDB.

## المميزات

**تشغيل**
- إيكوليزر 5 حزم مع إعدادات جاهزة، ودمج تدريجي بين الأغاني (crossfade) اختياريًا
- سرعات تشغيل مع **الحفاظ على النغمة** (preservesPitch)
- مؤقت نوم (دقائق معدودة أو نهاية الأغنية)
- **استمرارية الجلسة**: الطابور وموضع التشغيل يُحفظان — أغلق التطبيق وارجع لنفس الثانية (v4)
- مزامنة كلمات LRC متتبعة (تصعد وتهبط معك عند التقديم والترجيع) (v4)
- كلمات ملفات .lrc، إيقاف نهائي من إشعار النظام (stop) (v4)

**مكتبة**
- قراءة وسوم وأغلفة مدمجة من الملفات نفسها: ID3v2 (بما فيها CP-1256 العربي)، MP4/M4A (moov في البداية أو النهاية)، FLAC — في `tags.js` بدون أي مكتبة، مغطاة باختبارات
- قوائم تشغيل يدوية + مفضلة + الأكثر سماعًا + الأحدث
- بحث يشمل العنوان والفنان **والألبوم** (v4)
- استيراد مجلد كامل بشكل تكراري (File System Access API)
- نسخة احتياطية JSON للقوائم والمفضلة والكلمات والإعدادات، تُربط تلقائيًا بالملفات عند إعادة إضافتها
- حذف بتأكيد + تراجع لمدة 9 ثوانٍ للأغاني **وللقوائم** (v4)

**تكامل النظام (PWA)**
- تثبيت على أندرويد/سطح المكتب، فتح ملفات صوتية من النظام (file_handlers)، استقبال ملفات «مشاركة» من التطبيقات الأخرى (share_target)
- Media Session: تحكم كامل من شاشة القفل بما فيها stop (v4)
- إشعار «فيه نسخة جديدة» مع زر تحديث — لا تحديث صامت أبدًا
- فشل تخزين ملف مشارك يظهر تنبيهًا واضحًا بدل اختفائه بصمت (v4)
- تحذير عند حجز قاعدة البيانات بتبويب آخر (v4)
- CSP صارم (`script-src 'self'`)، رؤوس أمان، تخزين دائم (persistent storage)

## بنية المشروع

```
index.html    الغلاف الصفحي (لا سكربتات داخلية — CSP)
boot.js       نقطة التشغيل: عامل الخدمة + إشعار التحديث + استقبال الملفات من النظام
app.js        المحرك والواجهة كاملة (المحرك الصوتي، المكتبة، الطابور، الإعدادات)
tags.js       محلل وسوم ID3v2 / MP4 / FLAC من البايتات
songs.js      بيانات تبويب «الكتاب» (روابط يوتيوب فقط — لا تحميل)
sw.js         عامل الخدمة: shell كاش + صندوق مشاركة
style.css     التنسيق (RTL عربي كامل)
_headers      رؤوس Cloudflare Pages
vercel.json   نفس الرؤوس لفيرسيل
tests/        اختبارات node لمحلل الوسوم ومنطق الإصلاحات
```

## التشغيل محليًا

```bash
python3 -m http.server 8099
# ثم افتح http://localhost:8099 في كروم
```

(عامل الخدمة والتثبيت وfile_handlers وshare_target تحتاج https أو localhost.)

## الاختبارات

```bash
node tests/pwa.test.mjs
# توقع: 29 ناجح، 0 فاشل
```

الاختبارات تبني ملفات ID3v2/MP4/FLAC اصطناعية بالبايت وتتحقق من قراءة الوسوم والأغلفة، وتفحص وجود منطق الإصلاحات في الكود.

## النشر

### فيرسيل (موصى به — الرؤوس الأمنية تعمل كاملة)
1. ارفع المستودع إلى GitHub، ثم من [vercel.com](https://vercel.com): **Add New → Project → Import** المستودع.
2. الإعدادات تُكتشف تلقائيًا (static، بدون build). اضغط Deploy.
3. أو عبر CLI: `npm i -g vercel && vercel --prod`

### Cloudflare Pages
Workers & Pages → Create → Pages → Upload assets، أو:
```bash
npx wrangler pages deploy . --project-name musiqak
```

### GitHub Pages
يعمل كصفحة ثابتة لكن بدون رؤوس مخصصة (CSP اختيارية هنا). فعّل Pages من إعدادات المستودع فقط.

## التحديث
عدّل الملفات، ارفع `VERSION` في `sw.js`، وانشر من جديد. المستخدمون الحاليون يرون toast «فيه نسخة جديدة» ويعيدون التحميل بالموافقة. الأغاني المخزنة لا تتأثر بالتحديثات إطلاقًا.

## ملاحظات
- مسح بيانات الموقع في كروم يمسح الأغاني المخزنة — استخدم «تصدير نسخة احتياطية» من الإعدادات أولًا.
- تبويب «الكتاب» روابط يوتيوب رسمية فقط (يفتح خارج التطبيق).
- OGG/OPUS/WAV تحتفظ بعناوين من اسم الملف (لا محلل وسوم لهذه الحاويات بعد).
- iOS: يعمل كصفحة، لكن file_handlers/share_target غير مدعومين على سفاري — الدعم «أفضل جهد».
